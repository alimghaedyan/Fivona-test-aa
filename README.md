# Finova \| فینووا

**سامانه هوشمند مدیریت مالی شخصی**

Finova یک برنامه وب فارسی برای ثبت و مدیریت درآمدها و هزینه‌ها،
برنامه‌ریزی بودجه و تحلیل وضعیت مالی است. رابط کاربری با پشتیبانی از زبان
فارسی و چیدمان راست‌به‌چپ طراحی شده و پروژه با رویکرد توسعه محلی
(Local-first) پیاده‌سازی می‌شود.

> نام عمومی و رابط کاربری پروژه **Finova** است. ممکن است در بخش‌هایی از
> کد، مسیرها یا پایگاه داده همچنان نام داخلی `darik` دیده شود؛ این
> نام‌های داخلی به‌منظور حفظ سازگاری پروژه باقی مانده‌اند.

------------------------------------------------------------------------

## امکانات

### مدیریت مالی

-   ثبت، مشاهده، ویرایش و حذف تراکنش‌های درآمد و هزینه
-   دسته‌بندی تراکنش‌ها
-   نگهداری اطلاعات هر کاربر به‌صورت مستقل
-   مدیریت بودجه ماهانه بر اساس دسته‌بندی
-   نمایش خلاصه وضعیت مالی و گزارش‌های درآمد و هزینه

### تحلیل و قابلیت‌های هوشمند

-   **پیش‌بینی هزینه‌ها:** پیش‌بینی روند هزینه‌ها با استفاده از Prophet و
    استفاده از روش میانگین وزنی متحرک (WMA) در صورت ناموفق بودن اجرای
    مدل اصلی
-   **تحلیل الگوهای خرید:** استخراج اقلام یا دسته‌بندی‌هایی که به‌صورت
    پرتکرار در کنار یکدیگر ثبت شده‌اند، با استفاده از الگوریتم Apriori
-   **خوشه‌بندی وضعیت مالی:** گروه‌بندی ماه‌ها بر اساس شاخص‌های مالی با
    استفاده از K-Means
-   **شاخص سلامت مالی:** نمایش یک امتیاز خلاصه برای ارزیابی وضعیت مالی

> در دسترس بودن هر قابلیت تحلیلی به نصب وابستگی‌های مربوط، وجود داده کافی
> و معتبر و اجرای موفق سرویس Backend بستگی دارد. خروجی مدل‌های تحلیلی
> تخمینی است و نباید به‌عنوان توصیه مالی قطعی تلقی شود.

## راه‌اندازی Backend در ویندوز

دستورها را در PowerShell اجرا کنید.

### ۱. ورود به پوشه Backend

``` powershell
cd .\backend
```

اگر از پوشه اصلی پروژه شروع می‌کنید، ابتدا به مسیر پروژه بروید و سپس
دستور بالا را اجرا کنید.

### ۲. ساخت محیط مجازی

``` powershell
python -m venv .venv
```

### ۳. فعال‌سازی محیط مجازی

``` powershell
.\.venv\Scripts\Activate.ps1
```

اگر PowerShell اجازه اجرای اسکریپت فعال‌سازی را نداد، می‌توانید فقط برای
پنجره فعلی PowerShell از دستور زیر استفاده کنید:

``` powershell
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
```

سپس دستور فعال‌سازی را دوباره اجرا کنید.

### ۴. نصب وابستگی‌ها

اگر فایل `requirements.txt` در پوشه Backend وجود دارد:

``` powershell
python -m pip install -r requirements.txt
```

در غیر این صورت، وابستگی‌ها را مطابق فایل مدیریت بسته موجود در پروژه نصب
کنید. برای قابلیت‌های تحلیلی، نصب بودن کتابخانه‌هایی مانند `prophet`،
`mlxtend` و `scikit-learn` نیز لازم است.

### ۵. اجرای سرور

از پوشه `backend` و در حالی که محیط مجازی فعال است:

``` powershell
python -m uvicorn app.main:app --reload --host 127.0.0.1 --port 8000
```

در صورت اشغال بودن پورت 8000، می‌توان از پورت آزاد دیگری استفاده کرد؛ در
این حالت آدرس Backend در تنظیمات Frontend نیز باید با پورت جدید هماهنگ
شود.

پس از اجرا، مستندات API در آدرس زیر در دسترس خواهد بود:

``` text
http://127.0.0.1:8000/docs
```

## راه‌اندازی Frontend

در یک پنجره جداگانه PowerShell:

``` powershell
cd .\Frontend
npm install
npm run dev
```

Vite معمولاً آدرس محلی Frontend را در ترمینال نمایش می‌دهد. در پیکربندی
متداول این پروژه، آدرس آن:

``` text
http://localhost:5173
```

است. اگر پورت دیگری نمایش داده شد، از همان آدرس اعلام‌شده در ترمینال
استفاده کنید.

## APIهای تحلیل مالی

در نسخه فعلی، مسیرهای زیر برای تحلیل داده‌های مالی در نظر گرفته شده‌اند:

  مسیر                            کاربرد
  ------------------------------- -------------------------
  `GET /api/analytics/forecast`   پیش‌بینی هزینه‌ها
  `GET /api/analytics/patterns`   استخراج الگوهای پرتکرار
  `GET /api/analytics/clusters`   خوشه‌بندی ماه‌های مالی

پارامترهای هر مسیر و پاسخ دقیق آن را می‌توان از مستندات Swagger در
`/docs` مشاهده کرد.

## پایگاه داده و اطلاعات کاربران

پروژه از SQLite استفاده می‌کند. فایل پایگاه داده توسعه در مسیر زیر قرار
می‌گیرد:

``` text
backend/data/darik.db
```

نام فایل پایگاه داده همچنان `darik.db` است و با نام نمایشی محصول، یعنی
Finova، تفاوت دارد.

اطلاعات تراکنش‌ها و داده‌های مالی، اطلاعات خصوصی محسوب می‌شوند. فایل پایگاه
داده واقعی، نسخه‌های پشتیبان و داده‌های کاربران نباید در مخزن عمومی Git
قرار بگیرند.

برای اجرای پروژه روی سیستم جدید، پایگاه داده و ساختار اولیه آن باید
مطابق سازوکار فعلی Backend ایجاد یا آماده‌سازی شود.

## نکات مهم توسعه

-   برای اجرای دستورهای Python، ابتدا محیط مجازی Backend را فعال کنید.
-   نصب یک کتابخانه در Python سراسری سیستم، لزوماً آن را در محیط مجازی
    پروژه در دسترس قرار نمی‌دهد.
-   اگر Prophet اجرا نشود، سیستم ممکن است از WMA به‌عنوان روش جایگزین
    استفاده کند؛ این رفتار به معنی اجرای موفق Prophet نیست.
-   برای تحلیل الگوهای پرتکرار، کتابخانه `mlxtend` باید در همان محیط
    Python مورد استفاده Backend نصب شده باشد.
-   داده‌های آزمایشی و تراکنش‌های ساختگی را از داده‌های واقعی تفکیک کنید.
-   پیش از انتشار نسخه عمومی، تنظیمات CORS، احراز هویت، مدیریت خطا،
    اعتبارسنجی ورودی‌ها و حفاظت از اطلاعات حساس را بررسی کنید.

## امنیت و فایل‌هایی که نباید Commit شوند

موارد زیر نباید در مخزن Git قرار بگیرند:

-   محیط مجازی Python مانند `.venv/`
-   پوشه‌های `__pycache__/`
-   پوشه `node_modules/`
-   فایل‌های `.env` و اطلاعات محرمانه
-   فایل پایگاه داده SQLite و نسخه‌های پشتیبان آن
-   خروجی‌ها یا فایل‌هایی که حاوی اطلاعات واقعی کاربران هستند

نمونه‌ای از قواعد مناسب برای `.gitignore`:

``` gitignore
# Python
.venv/
venv/
__pycache__/
*.py[cod]

# Node
node_modules/
dist/

# Environment and secrets
.env
.env.*
!.env.example

# Local databases and backups
*.db
*.sqlite
*.sqlite3
*.db-journal
*.bak

# Editor / OS
.vscode/
.idea/
.DS_Store
Thumbs.db
```

اگر فایل پایگاه داده قبلاً با Git رهگیری شده باشد، اضافه کردن آن به
`.gitignore` به‌تنهایی آن را از مخزن خارج نمی‌کند؛ باید رهگیری Git آن
به‌صورت آگاهانه و بدون حذف فایل محلی متوقف شود.
